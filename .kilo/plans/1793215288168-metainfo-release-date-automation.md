# Plan: Automate AppStream release dates from git tag dates

## Problem
`scripts/sync_version.py:166` stamps `datetime.date.today().isoformat()` on every new `<release>`, and `scripts/generate_appstream_notes.py:288` defaults the same. Batch-synced releases therefore share one placeholder date (e.g. 0.3.12's tag is 2026-10-27 but its metainfo date is stale 2026-10-25; 0.3.11/0.3.12 share 2026-10-25). The `.in` template is source of truth; `.xml` is regenerated by `scripts/i18n.py metainfo`. No release-date metadata exists in the repo.

## Decisions
1. **Date source**: each release's git tag commit date in UTC (`git log -1 --format=%ci v<ver>` → UTC date). Best available proxy for real publish date.
2. **Collision handling (user hard constraint: no date reused across versions)**: process versions high→low; if the computed UTC date is already assigned to a higher version, increment by one day until free. Fully deterministic from git data — no manual date entry. Same-day ships (0.3.0–0.3.3 on 10-21, etc.) get staggered calendar dates.
3. **Scope**: update both `flatpak/*.metainfo.xml.in` (template) and regenerate `flatpak/*.metainfo.xml` via `scripts/i18n.py metainfo`.
4. **Future-proof**: make `sync_version.py` and `generate_appstream_notes.py` use the git tag date (fall back to `today()` only if tag has no commit date) instead of unconditional `today()`.
5. **Validation**: all `<release>` dates non-null, unique, parseable `YYYY-MM-DD`; wire into `scripts/sync_version.py --check` and CI.

## Tasks
1. Add `get_tag_date_utc(version)` helper (git tag → UTC date string `YYYY-MM-DD`; fallback `None`).
2. Add `assign_unique_release_dates(versions)` → `{version: date}` using high→low processing + day-stagger on collision.
3. Modify `scripts/sync_version.py::update_metainfo`: date = tag date for the version being synced (fallback `today()` if no tag date).
4. Modify `scripts/generate_appstream_notes.py`: CLI `--date` default = tag date when `--version` resolves to a tag; fallback `today()`.
5. Rewrite release `<release date="...">` attributes in `flatpak/*.metainfo.xml.in` using assigned dates.
6. Run `uv run python scripts/i18n.py metainfo` to regenerate `flatpak/*.metainfo.xml` from template.
7. Add date validity/uniqueness check to `scripts/sync_version.py --check` (or new check) and CI.
8. Validate: `uv run python scripts/sync_version.py --check`, `uv run python scripts/i18n.py metainfo --check`, `PYTHONPATH=src uv run pytest -v tests/`.

## Rollback
Revert `flatpak/*.metainfo.xml(.in)` and `scripts/sync_version.py`, `scripts/generate_appstream_notes.py` via git; dates return to previous (placeholder) state, no data loss.

## Exit criteria
- Every `<release>` has a non-null, unique `date="YYYY-MM-DD"`.
- Dates derive from git tag commit dates (UTC), staggered only on same-day collision.
- `sync_version.py --check`, `i18n.py metainfo --check`, and pytest all pass.
